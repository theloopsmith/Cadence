02 / WHAT THE MODELS DO

The right tool.
A bounded job.

Model authorship and hosting are different. These are the preferred configured Meta paths, with local code around every call.

META MODEL · BASETEN HOSTING

Muse Spark Open

meta-models/muse-spark-open-1026

Classifies conversational requests into allowed intents. For a grounded scene description, can choose an object label from the labels SAM already found.

Question → allowed intent → saved-record lookup
The phone constructs factual answers from its records. The model does not invent dose times or execute actions.
META MODEL API

SAM 3.1

sam-3.1

Segments named concepts in the photo the user chose. Backend filters mask evidence and uses constrained descriptions with explicit uncertainty.

Confirmed photo → masks → grounded label
A detected object is an image observation. Missing evidence does not prove a person or hazard is absent.
META MODEL API · OPTIONAL ONLINE INPUT

Muse Voice Transcribe

muse-voice-transcribe-1.0

Transcribes an opted-in voice clip into text. The companion can combine that with Apple’s on-device recognizer and keep the current task context.

Audio → text → current conversation step
This is speech recognition, not a spoken-reply model. Installed Apple voices speak replies; the web tour uses browser speech.
Where does Llama fit?

The companion also supports configured Meta Llama 3.3 through Fireworks when the Baseten key is absent. It is an alternate configuration, not an automatic retry after a failed Muse request. Llama 3.2 vision adapters also remain in the repository; the current surroundings route uses SAM evidence and bounded label selection.

Hosting services are not new model authors. No ElevenLabs voice model is used.

ORDINARY SOFTWARE

Apple speech output · on-device recognition · Accelerate FFT · OpenCV · SQLite. These are platform features, math and storage—not additional external inference calls.

More energy in the higher band relative to the step band produces a larger ratio. A small ε prevents division by zero.

  1. Available motion, with iPhone fallback
  2. Walking, initiation or upright-turn context
  3. Energy floor + repeated qualifying windows

Hann window + FFT. Three qualifying 0.5-second hops are required to start an episode. Speech changes the trigger. Thresholds are experimental; this is not a diagnostic measure.

04 / HANDWRITING OBSERVATIONS

A photo becomes
a measurable comparison.

OpenCV thresholds the image, deskews the line, finds connected ink components and orders them left to right. It compares average component heights near the start and end.

Synthetic boxes, not measurements taken from the photo above.

CHANGE IN STROKE HEIGHT

(end − start) ÷ start × 100
—
Start average40 pxEnd average32 px

The first and last groups each use roughly one-third of the accepted components, with at least two in each group. Fewer than four components means “unreadable,” not a perfect result.

Camera angle, cursive joins and image quality affect this estimate. The app keeps observations and unavailable/skipped states separate. Research scores are hidden by default. SAM is not the primary handwriting-measurement engine.

05 / THE OTHER MOMENTS

Simple rules.
Careful follow-through.

01

Voice sample

Over the sustained vowel, Cadence measures average level and variability of the level samples.

RMS = √mean(sample²)
dBFS = 20 × log₁₀(RMS)Variability is the standard deviation of dBFS samples. Voice quality gates can require a retry; silence is not reported as a valid sample.
02

Walking task

A guided ten-second sample records available movement observations. The phone’s local gait pipeline supplies cadence and FoG-related observations.

Movement → local analysis → recorded observation
Skipped, unavailable and measured tasks are kept distinct. The browser walkthrough performs no sensor measurement.
03

Possible fall

Impact, jerk and orientation changes feed deterministic detection. A candidate starts a check-in before any unresolved alert can escalate.

Candidate → check-in → durable escalation state
Emergency decisions are not delegated to an LLM. The demo simulates caregiver delivery; the app is not an emergency service.
04

Medication diary

Saved routine lookup and record queries use app logic. An explicit statement and confirmation produce a timestamped event.

Saved facts → confirmation → diary record
No dose recommendation or inference of ingestion. Meal logging stores a timestamp; nutrition advice is outside the submitted scope.

06 / WHAT MAKES IT A COMPANION

The request ends.
The responsibility continues.

Account-bound offline queues. Records are kept with their wearer and retried; changing a server does not silently reassign someone’s history.

Crash recovery. Persistent SQLite state and a recovery loop resume open server-side alert work after restart.

Evidence, kept separate. A queued event, provider acceptance, delivery status and human acknowledgment represent different facts.

Keys stay server-side. HTTPS, scoped login roles and a read-only dashboard protect the cloud demo. No provider key is embedded in the app or this page.

Hackathon prototype. Illustrative animations and math examples do not establish clinical accuracy, physical-device acceptance or real caregiver delivery.
